# 真实过程记录与导出

在画第一批之前阅读。先确认当前环境确实能渲染 SVG、查看 PNG 和播放导出的记录；不把某个库可导入当作完整能力验证。使用已有浏览器、SVG 渲染器和视频工具，不为每张图建立新框架。

## 文件与记录时机

建议每张作品独立保存：`source/` 放绘制源码与工作 SVG，`process/` 放不可覆盖的历史快照，`output/` 放成稿与回放。目录名可适应项目。

1. 第一批草稿完成后立即渲染、查看并保存快照；如果记录空白画布，也必须在创作开始时实际保存。
2. 此后在主要阶段和有意义的改动后重复，**修改下一批前先保存本批**。保留真实回退、删除、移动与修改，不只记录单调增加图层的阶段。
3. 每条说明只写刚刚实际发生的变化和观察，不事后编造工作日志。过程的粒度是批次，不是逐笔。
4. 最后一次调整后再记录一次；确认这个 SVG 就是交付成稿。

可以使用连续录屏或自有记录器。使用附带 `scripts/record_process.py` 时，它仅用 Python 标准库，将**调用时提供的** SVG 与 PNG 原样保存为新编号目录，记录 UTC 时间、说明和 SHA-256。它不渲染、不证明图像与源码的对应关系，也不能独立证明历史真实性；你必须先从该 SVG 实际渲染 PNG，再立即记录。不要用最终稿反向构造历史来调用它。

下列 `SKILL_DIR` 表示本次实际加载的 Skill 目录，`ART_DIR` 表示本张作品目录；使用时替换成真实路径，不要求用户配置这些参数。

```text
python "SKILL_DIR/scripts/record_process.py" capture --root "ART_DIR/process" --svg "ART_DIR/source/current.svg" --png "ART_DIR/source/current.png" --note "草稿：确定主体轮廓和前后遮挡"
```

每次记录创建 `0001/`、`0002/` 等目录，内含 `state.svg`、`preview.png`、`checkpoint.json`。旧目录不覆盖。相邻完全相同的源码与预览会被拒绝，避免把重复保存当作进展。记录失败时先检查原始文件和不完整目录，不把失败调用当作成功，也不盲目补写历史。

## 渲染

选择实际可用的浏览器、Inkscape 或其他支持所用 SVG 效果的渲染器。先验证一张简单文件，再用于作品。浏览器截图应只截画布，等 SVG 和字体就绪后再截；需要透明背景时显式保留 alpha。防止页面边距、缩放和设备像素比改变导出尺寸。

工作快照可以小于交付分辨率，但应足以看出该批修改。PNG 最终预览的默认长边是 3000 像素，按 SVG 画幅等比导出。不能仅把文件名写成 3000px；读取真实像素尺寸并检查画面裁切。最后一张工作快照与最终 PNG 可以分辨率不同，但必须来自同一个最终 SVG。

## 离线 HTML

```text
python "SKILL_DIR/scripts/record_process.py" replay --root "ART_DIR/process" --final-svg "ART_DIR/output/art.svg" --output "ART_DIR/output/process.html" --title "本次作品的制作过程"
```

回放器按编号播放真实 PNG，提供播放/暂停、重播和进度跳转。PNG 内嵌于 HTML，离线无需网络或原目录；保存的 SVG 与元数据仍应随原始材料交付。说明会标为“真实批次快照回放，非逐笔录像”。工具要求至少两条记录、检查历史文件散列，并要求末条 SVG 与 `--final-svg` 完全一致；不一致时先追加真实最终状态。

在浏览器中打开实际生成的 HTML，检查首帧、播放、暂停、跳转、结尾停留和窄屏布局。确认没有加载外部资源或运行错误，标签含特殊字符时也应显示为文本。

## 视频优先

有可用的视频编码器时，优先将上述真实 PNG 序列或录屏导出为 MP4/WebM。复用已验证的环境命令，先检查工具的本地帮助与编码器能力；不要只因能执行 `ffmpeg` 就声称成功导出。

- 按实际编号排列，保持真实顺序；可压缩等待时间、调节各批停留时间和加入说明，不插造绘制状态。
- 统一视频画布尺寸，等比缩放并留边，不能裁掉作品重点；透明画稿选择协调的回放衬底，SVG 与 PNG 的透明要求单独保留。
- 末帧展示完整成稿并给予可辨认的停留时间。实际播放或解码核验时长、帧数、编码结果和末帧。
- 视频导出不可用或失败时，交付已验证的离线 HTML 并说明原因，不把静态预览称作动画。

## 不完整过程的处理

如果较晚才开始记录，明确说明缺失了哪些阶段。不要用成稿倒推草稿，也不能把演示动画标成真实制作过程。恢复已有作品时保留现存历史；当前任务只新增真实发生的记录。
